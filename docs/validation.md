# 검증 기록

검증일: 2026-11-19. 개발 환경은 macOS arm64, Java 21.0.9, Node.js 23.7.0, Codex CLI 0.169.0, Chrome입니다. 배포 시 Node.js는 22/24 LTS를 권장합니다. Windows·Linux 실기기 검증은 수행하지 않았습니다.

Hub 비밀번호 제거 후 `npm run setup`으로 토큰 설정을 생성하고, Java 테스트 7개와 Agent 테스트 17개를 통과했습니다. 실제 Chrome에서 로그인 화면 없이 Hub에 접속하고 Agent에 연결해 Express Preview와 요소 선택을 확인했습니다. 이 변경에서 실제 Codex 호출은 생략했습니다. 아래 기록은 이전 로그인 방식에서 수행한 검증입니다.

## 실제 브라우저 검증

`tests/workflow.spec.ts`는 개인 로그인 상태의 실제 Codex App Server를 호출했습니다. 모의 AI 응답으로 성공 처리하지 않았습니다. 최종 신규 작업의 전체 테스트는 22.5초에 통과했습니다. 별도의 완료 작업 복구 테스트는 필요할 때만 실행하므로 기본 실행에서 skip되는 것이 정상입니다.

Express/EJS에서 확인한 흐름:

1. Hub 로그인과 본인 Agent 연결.
2. 등록된 프로젝트 선택, 현재 디스크 기준 작업본 생성, 등록된 npm 설치·Node 서버 실행.
3. 실제 EJS 렌더링 페이지에서 검색 영역 클릭, DOM 구조 첨부. 선택 정보에 주변 고객 이름·입력값이 없는지 확인.
4. 개인 IDE의 MCP/플러그인 설정을 가져오지 않는 별도 Codex App Server에 수정 요청.
5. `views/index.ejs`의 h1을 `주문 관리`에서 `주문 내역`으로 실제 수정.
6. 변경 파일 감지, Preview의 새 제목 확인, Monaco 파일 목록에 변경 1개 표시.
7. 적용 직전 원본 SHA-256이 작업 시작 시점과 같음을 검증.
8. UI에서 파일 적용 승인, 원본 SHA-256 변경 확인.
9. UI에서 백업 복구 승인, 원본 SHA-256이 시작 시점과 같아짐을 검증.

React·Spring은 브라우저 테스트 각각 4.0초·13.1초에 통과했습니다. 이 기록은 해당 예제 구성이 동작했다는 의미이며 모든 버전·프로젝트의 호환성 보장이 아닙니다. 최종 정책·실행 JAR 경로를 분리한 후 Spring을 추가 회귀 검증했습니다.

로컬 등록 화면은 HTTP 테스트로 잘못된 Origin·토큰 차단과 설정 저장·원본 보존을 검증했습니다. 등록 폼을 사람처럼 조작하는 별도 브라우저 테스트는 실행하지 않았습니다.

## 검증 중 수정한 문제

- Spring Security 설정 클래스와 Bean 이름 충돌: 실제 전체 컨텍스트 시작 테스트를 추가했습니다.
- Vite base와 프록시 경로 불일치: 프레임워크 공통 코드를 무작정 바꾸지 않고 task prefix 설정과 Vite base로 처리했습니다.
- Java의 IPv4-mapped 바인딩이 Seatbelt에 막힘: IPv4 소켓 사용으로 해결했으며 샌드박스를 해제하지 않았습니다.
- 실행 중인 JAR을 재빌드로 덮어쓰면 지연 클래스 로딩이 실패함: Hub는 실행 JAR을 분리하며 Agent의 Java 실행본도 별도 위치로 복사합니다.
- 개인 IDE MCP가 작업 디렉터리 밖 권한을 가질 수 있음: 로그인만 복사하는 격리된 `CODEX_HOME`으로 실행합니다.
- 런타임 정책/산출물이 작업본 안에 있으면 프로젝트 코드에 의해 바뀔 수 있음: 정책과 JAR은 작업본 밖 Agent 전용 경로에 보관하고 캐시 링크를 차단합니다.

## 남은 검증과 제한

- Windows/Linux 명령 실행 격리, macOS 외 실기기, 여러 OS 사용자/네트워크 파일시스템의 잠금.
- Java/React에서 AI가 서버 로직까지 수정한 전체 적용 시나리오, Spring 재빌드 실패 시 마지막 정상 상태의 장시간 유지.
- App Server의 권한 요청·중단에 대한 실제 모델 시나리오, CLI 버전별 프로토콜 호환성.
- 로그인 실패 반복 제한·SSO·멀티 계정의 실제 브라우저 E2E·외부 HTTPS/WSS 배포.
- CSP/인증이 복잡한 실제 업무 사이트, 동적 절대 URL·쿠키·POST·HMR WebSocket 프록시.
- 디스크 부족·전원 장애·강제 종료의 실제 하드웨어 장애 주입. 일반 파일 쓰기 실패는 자동 롤백 테스트로 확인했습니다.
- SQL은 변경 주의 표시와 사람 검토까지만 제공합니다. SQL 파서·정밀 위험 판정·DB 실행은 구현하지 않았습니다.

전체 개발 지침의 모든 항목을 완료한 것으로 표시하지 않습니다. 현재 완료 기준은 기존 소스에 Inspector를 설치하지 않는 Express의 실제 AI 수정·검수·원본 적용과 복구, 그리고 두 추가 프레임워크의 실제 Preview 검증입니다.
